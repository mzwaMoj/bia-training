Topic 1

Framing the prediction

❓What exactly are we trying to predict?
Big ideaUse machine learning when historical examples can help you estimate something unknown. Don't use it when a simple calculation already gives you the answer.

Three ways of working with data

1

Descriptive analysis

Understand what already happened. "What was the average house price?" The prices are already in the data, so you just calculate the average.

2

Fixed calculation

Apply a known rule. A 2% service fee on R10,000 is 10,000 × 0.02 = R200. No learning needed.

3

ML prediction

Estimate something not yet known using patterns in past data. "What will this new house sell for?"

Features (X) and target (y)

Features (X) are the input information the model uses. The target (y) is the answer we want it to predict. The model learns the relationship between X and y from historical rows; for a new property we supply X and it estimates y.

Types of machine learning

🏷️ Supervised

Learns from examples where the correct answers are known. Predicting house prices from past sales. Two tasks: regression (predict a number) and classification (predict a category).

🧩 Unsupervised

Looks for patterns without answers. Grouping customers by their shopping behaviour.

🤖 Reinforcement

Learns by taking actions and receiving rewards or penalties. A warehouse robot learning to avoid obstacles.

Our projectPredicting a house price is supervised learning, specifically regression, because the target is a number and we have past prices to learn from.

Data doctor

Every token below appears in the real practical file. Pick the right treatment for each one.

Missing values and imputation

A missing value means information is not available in a record. You can remove the whole row (and lose useful information) or impute: fill the gap with a chosen value.

Mean imputation

The average. Areas 4,000, 5,000, 6,000:

mean = 4000 + 5000 + 60003 = 5000

Median imputation

The middle value once sorted. 3,000, 4,000, 5,000, 6,000, 20,000:

median = 5000  but  mean = 7600

The single 20,000 value pulls the mean upwards. That's why the median is often safer when numbers contain extreme values. For categories, use the mode, the most frequent value: furnished, unfurnished, furnished, furnished → furnished.

Training data onlyThe mean, median and mode used for filling must be calculated from training data only, then reused unchanged on validation and new records. Otherwise held-out data leaks into preparation.

Outliers and the IQR method

An outlier is a value unusually far from most others. It might be an error, or it might be a genuine luxury property. The IQR rule flags values for investigation:

IQR = Q3 − Q1·upper = Q3 + 1.5 × IQR
IQR = 6405 − 3600 = 2805→6405 + 1.5 × 2805 = 10,612.5

Topic 3

Representing mixed features

❓How do we turn different types of information into something a model understands?

🔢 Numerical features

Measured with numbers: area = 5,000 · bedrooms = 3 · bathrooms = 2 · parking = 1.

🏷️ Categorical features

Groups, not measurements: furnishing = furnished · main road = yes · air conditioning = no.

Most algorithms need numbers, so categories must be transformed.

One-hot encoding

One-hot encoding turns each category into its own 0/1 column. 1 means "this category applies", 0 means it doesn't.

PropertyFurnishingfurnishedsemi-furnishedunfurnished
AFurnished100
BUnfurnished001
CSemi-furnished010
Why not furnished = 3, unfurnished = 1?Numbers like that invent an order and a distance between categories that don't exist. One-hot columns represent categories without that false ranking.

What about a category the model has never seen?

The encoder learned furnished, semi-furnished and unfurnished from training. A new listing arrives as part-furnished. With OneHotEncoder(handle_unknown="ignore") the pipeline doesn't crash; the furnishing block becomes [0, 0, 0]. That doesn't mean "unfurnished", only "not recognised". In a real system, new categories may need investigation or a model update.

Two ways to scale area

Feature scaling

Area is measured in thousands while bedrooms sit in single digits. Some algorithms let the big-numbered feature dominate. Scaling puts numerical features on comparable scales.

A. Standardisation

z = x − μσ

Area 6,500, mean 5,000, std 1,000: z = (6500 − 5000) / 1000 = 1.5. The area is 1.5 standard deviations above the training mean.

B. Min-max scaling

xscaled = x − xminxmax − xmin

Min 1,000, max 9,000, area 5,000: (5000 − 1000) / 8000 = 0.5.

StandardisationMin-max scaling
Uses mean and standard deviation.Uses minimum and maximum.
Centres values around zero.Maps training values into 0–1.
Values can be negative or positive.New values can fall outside 0–1.
Does not make data normally distributed.Does not remove outliers.
Same rule againBoth scalers learn their statistics from training data and reuse them on validation and new data. Not every algorithm needs scaling (tree models usually don't).

Feature engineering

Feature engineering creates new features from existing information. From area 6,000 and 3 bedrooms:

area_per_bedroom = 60003 = 2000
Try it: a safe ratio
Allowed vs forbiddenarea_per_bedroom is allowed: it uses only information available before the sale. price_per_area_at_sale is forbidden: it uses the price we're predicting. And creating a feature doesn't guarantee it helps; that has to be tested later with a model that actually learns from features.

Topic 4

Protecting your data

❓How do we make sure our model is evaluated fairly?
Big ideaYou know how to clean and prepare the data. Before any model, imputer or scaler learns from it, we lock away the evidence. One of the biggest mistakes in machine learning is letting the model see information it should not have seen, so we split first and keep held-out data out of every learning step.

Training, validation and test data

After removing duplicates, the practical has 545 property records. They are divided into three groups:

Training · 327teach the model
Validation · 109compare choices
Test · 109final exam

A. Training

The data the model learns from: sizes, bedrooms and prices.

B. Validation

Used to compare models and choose an approach. It must not be used to fit the model being evaluated.

C. Test

Reserved for the final evaluation, only after all development decisions are made.

Exam analogyTraining data = studying the textbook. Validation data = practice tests. Test data = the final exam. If you peek at the exam answers first, you haven't fairly tested your knowledge.

Why do we shuffle?

The practical CSV is sorted from the most expensive house to the cheapest. If you take the first 60% as training, the model learns mostly expensive homes and is judged on cheap ones. Shuffling randomly rearranges records before splitting. random_state=42 makes the shuffle reproducible.

What is data leakage?

Data leakage happens when information that should not be available during training influences learning or evaluation. It makes a model look better than it really is.

The CSV contains a column called price_per_area_at_sale. Look at how it was made:

price per area =selling priceproperty area← it contains the answer!
Which features may we use?

✓ Property size

✓ Number of bedrooms

✓ Number of bathrooms

y Actual selling price: this is our target

✗ Price per area at sale: it uses the target

Other ways leakage sneaks in
  1. Using validation or test data to calculate averages, medians or scaling values.
  2. Duplicate records landing in both training and validation.
  3. Using test results repeatedly to make development decisions.

Data validation vs model validation

🧾 Data validation

Is the dataset clean and correctly structured?

  • Are there missing values?
  • Are there duplicate records?
  • Are numerical columns actually numbers?
  • Are the categories valid?

📏 Model validation

How well does the model predict data it was not trained on?

  • Are the house-price predictions reasonable?
  • How large are the prediction errors?
You need bothA dataset can be clean while the model performs badly. And a model can produce a good-looking score from incorrect or leaked data.

Building a pipeline

❓How do we combine all the preparation steps into one workflow?
Big ideaA pipeline is a production line: raw property data goes in, passes through each preparation station in order, and comes out as a prediction. The same stations, with the same fitted settings, process training, validation and brand-new rows.
Raw property data12 columns: area, bedrooms, furnishing…
↓
Fixed cleaning rulesparse "5,400", fix " YES ", invalid → missing, add area_per_bedroom
↓
Numerical branchmedian imputer → StandardScaler
Categorical branchmost-frequent imputer → OneHotEncoder
↓
Combine prepared features6 numerical + 15 one-hot = 21 columns
↓
Prediction modelproduces an estimated house price

Three building blocks

Transformer changes or prepares data.
SimpleImputer, StandardScaler, OneHotEncoder
Estimator is the model that learns to predict.
LinearRegression, DecisionTree, RandomForest, DummyRegressor
Pipeline connects the steps in the correct order so the whole process runs together.

fit, transform, predict

OperationMeaning
fit()Learn settings or patterns from data.
transform()Apply the learned preparation settings.
predict()Generate predictions.
fit_transform()Learn and apply in one step (training data only).

Fit a median imputer on training areas 4,000, 5,000, 6,000 and it learns 5,000. When a validation row has a missing area, transform() fills it with that same 5,000. It does not compute a new median from validation data. That's what prevents leakage.

from sklearn.impute import SimpleImputer

imputer = SimpleImputer(strategy="median")
X_train_clean = imputer.fit_transform(X_train)   # learn AND apply
X_val_clean = imputer.transform(X_val)           # only apply

ColumnTransformer: different routes for different columns

Numerical columns need imputation and scaling; categorical columns need imputation and encoding. ColumnTransformer sends each group down its own branch and joins the results.

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.dummy import DummyRegressor

numeric_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])
categorical_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("encode", OneHotEncoder(handle_unknown="ignore")),
])
columns = ColumnTransformer([
    ("num", numeric_pipe, NUMERIC_COLUMNS),
    ("cat", categorical_pipe, CATEGORICAL_COLUMNS),
], remainder="drop")

model = Pipeline([
    ("columns", columns),
    ("baseline", DummyRegressor(strategy="median")),
])
model.fit(X_train, y_train)          # every step learns from training rows only
RememberA pipeline automates preparation and guarantees the same rules are applied consistently to training, validation and new data.

Creating an honest baseline

❓How do we know whether a model is actually performing well?
Big ideaA baseline is a deliberately simple model that gives you a reference point. If a sophisticated model can't beat "predict the same price for everyone", it hasn't learned anything useful.
PropertyActual priceBaseline prediction
AR3,000,000R4,000,000
BR4,000,000R4,000,000
CR5,000,000R4,000,000
DR6,000,000R4,000,000

DummyRegressor

scikit-learn's DummyRegressor ignores the features and predicts one number using a strategy: mean (average training price), median (middle training price) or constant (a fixed value). We use the median, calculated from training targets only.

from sklearn.dummy import DummyRegressor

baseline = DummyRegressor(strategy="median")
baseline.fit(X_train, y_train)            # learns the training median price
print(baseline.predict(X_val)[:3])
[4305000. 4305000. 4305000.]

Why the median instead of the mean?

R2m, R3m, R4m, R5m, R20m→mean = 2+3+4+5+205 = 6.8m·median = 4m

One R20m property drags the mean up. There's also a neat mathematical reason: the median is the single number that minimises the total absolute error on the training targets. So if you'll be judged by absolute error (MAE), the median is the natural constant. See it for yourself:

Evaluating with MAE

❓How far are our predictions from the actual prices?

Mean Absolute Error

MAE is the average size of the model's errors, ignoring whether each guess was too high or too low.

MAE = (1/n) Σ |yᵢ − ŷᵢ|
n
number of observations
yᵢ
actual value
ŷᵢ
predicted value
| |
absolute value: removes the minus sign

Reading MAE results

  • Lower MAE = better predictions.
  • Higher MAE = larger errors.
  • Zero MAE = perfect on the evaluated records.

CarefulMAE is not an accuracy percentage. An MAE of R40,000 does not mean "96% accurate". And a lower MAE doesn't automatically mean a model is profitable, fair or suitable for a business decision.

Topic 8

Cross-validation

❓Is the model's performance consistent across different groups of data?
Big ideaOne validation set might be unusually easy or hard. Cross-validation evaluates the model several times, each time holding out a different part of the development data, and averages the results.

K-fold cross-validation

Split the development data into k folds. Each round trains on k − 1 folds and validates on the remaining one, so every fold gets one turn as validation.

🧪 Lab 11

Fold runner: median baseline on the 436 development rows

Step through the rounds. Each round refits the whole pipeline on its training folds, then scores its validation fold. The reserved test set never takes part.

Number of folds
Rounds
Inside every round
  1. Learn median, scaling, categories from this round's training folds
  2. Fit the baseline on those folds
  3. Transform & score the validation fold
TrainValidateReserved test (outside CV)

Calculating the CV score

Round 1R50,000
Round 2R60,000
Round 3R40,000
CV MAE = 50,000 + 60,000 + 40,0003 = R50,000

The rule that keeps CV honest

Every fold must learn its own preparation settings from its training portion only: its own median, its own scaling values, its own category vocabulary. Then it applies them to its validation fold.

✗ LeakyClean, impute and scale all development data once, then cut it into folds. Every validation fold has already influenced the medians and scaling.
✓ HonestPass the whole pipeline to cross-validation so it is refitted inside every round. The test set stays outside entirely.
from sklearn.model_selection import KFold, cross_val_score

scores = cross_val_score(
    median_model, X_dev, y_dev,                 # whole pipeline, development rows only
    cv=KFold(n_splits=3, shuffle=True, random_state=42),
    scoring="neg_mean_absolute_error")
print(-scores.mean())
RememberCross-validation shows whether performance is consistent across splits. It does not replace the final test evaluation.
