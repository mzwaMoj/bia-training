What is maths for machine learning?

Machine learning means teaching a computer to find patterns in data and use them to make predictions. Maths is how the computer stores that data, makes a guess, checks how wrong the guess was, and gets better.

All through this lesson we use one story: you own an online store and want to predict how much a customer will spend.

The big picture: the training loop

Every topic is one piece of this loop. By the end you'll be able to explain each step:

  1. Data goes in as vectors and matrices.
  2. The model predicts using a dot product.
  3. It measures its mistakes with a loss.
  4. The gradient says which way to adjust.
  5. Gradient descent updates the weights.
  6. Repeat until the predictions are good.

Vectors

❓How is one order written as numbers?
Big ideaA vector is just a list of numbers in a fixed order. In machine learning, one vector describes one thing: one customer, one order, one house.

One order = one vector

A customer places an order. We note three facts about it. Each fact is called a feature, a piece of information the model can use.

3Products

5Rating
x =3105← products, distance, rating
Order matters[3, 10, 5] and [10, 3, 5] are different customers. The model always expects the features in the same positions.

Where do vectors live? In your tables.

Most of the time your data sits in a table: an Excel sheet or a pandas DataFrame. Here's the key idea:

Adding vectors

Add vectors position by position. They must be the same length. Example: Customer A orders 2 products from 5 km away, Customer B orders 3 products from 10 km away.

Magnitude: how long is the arrow?

Draw a vector as an arrow from the origin. Its magnitude is the arrow's length, worked out with Pythagoras:

Adding matrices

Just like vectors: same shape, add matching positions.

1234+5678=681012

Multiplying matrices, made simple

Forget the formula for a moment. Matrix multiplication is just "quantity × price, then add it up", done for many customers at once.

Step 1: one customer (like a till slip)

Customer A buys 2 products and lives 5 km away. The shop charges R100 per product and R10 per km.

(2 × 100) + (5 × 10) = 200 + 50 = R250

Multiply each pair, then add. That's all a "row times column" is.

Step 2: two customers at once

Put each customer on a row and the prices in a column. Each customer's row walks across the price column and produces one answer.

25310customers· 10010prices= 2×100 + 5×103×100 + 10×10working= R250R400one answer each

Customer A (row 1) → R250. Customer B (row 2) → R400. One calculation gives a prediction for every customer, whether there are 2 or 2 million.

Step 3: the shape rule, in plain words

(2customers × 2features) · (2prices × 1price list) = (2customers × 1answer each)
Middle numbers must matchEvery feature needs its own price to pair with. 2 features ↔ 2 prices ✓.
With 3 features but only 2 prices, one feature has no partner, so the multiplication can't be done ✗.
Outer numbers = size of the answerOne answer row per customer, and one answer column per price list.
2 customers, 1 price list → a 2 × 1 answer: two predictions.

Bigger example

(4customers × 3features) · (3weights × 2weight lists) = (4customers × 2answers each)

4 customers, each described by 3 features. 2 different weight lists: say, one predicts spend and another predicts delivery time. The middle 3s match, so it works. Every customer gets 2 answers → a 4 × 2 table.

Quick trickWrite the two shapes side by side: (4 × 3)(3 × 2). If the middle numbers are the same, you can multiply. The answer's shape is the outside numbers: (4 × 2). The "row × column, add up" step is the dot product, covered in Topic 3.

Topic 3

Dot products

❓How do features and weights make a prediction?
Big ideaA dot product multiplies matching pairs of numbers and adds the results. It's exactly how a till slip works: quantity × price for each item, then add it all up.

Step 1: pair them up, multiply, add

A customer orders 3 products and lives 10 km away. The model has learned two weights: R100 per product and R5 per km. Each feature is paired with its own weight (same colour = same pair):

FeatureValue (x)Weight (w)Contribution
Products3×100=300
Distance (km)10×5=50
Add them upR350

Written as vectors, it's exactly the same calculation:

310features x· 1005weights w= (3 × 100) + (10 × 5)pair up= 300 + 50add= 350one number
The whole idea in one lineTwo lists in → one number out. Multiply the 1st with the 1st, the 2nd with the 2nd, …, then add everything.

Step 2: add the bias

A bias is a fixed amount added at the end, like a flat service fee. It means the prediction doesn't have to be R0 when every feature is 0. With a bias of R50:

ŷ = x · w + b = 350 + 50 = R400

Step 3: the one rule, same length

Works ✓[3, 10] · [100, 5]
2 features, 2 weights: every feature has a partner.
Doesn't work ✗[3, 10, 5] · [100, 5]
3 features but only 2 weights: the rating (5) has no weight to pair with.

This is the same "middle numbers must match" rule you saw with matrices in Topic 2.

Step 4: many customers at once (matrix × vector)

Stack the customers as rows of a matrix. Each row does its own dot product with the same weights, so you get one prediction per customer:

31012518customers X (3 × 2)· 1005weights w (2 × 1)= 3×100 + 10×51×100 + 2×55×100 + 18×5each row · w= 350110590predictions (3 × 1)
CustomerRow vectorRow · w+ bias 50
A[3, 10]300 + 50 = 350R400
B[1, 2]100 + 10 = 110R160
C[5, 18]500 + 90 = 590R640

That's why ML loves matrices: one multiplication, X · w + b, gives predictions for 3 customers or 3 million.

Step 5: what the weights tell you

Keep the same customer [3 products, 10 km] and change only the weights. Each weight says how much its feature matters, and in which direction:

Weights [product, km]WorkingPredictionWhat it means
[100, 5]300 + 50R350Both features push the price up.
[100, 0]300 + 0R300Weight 0: distance is ignored.
[100, −5]300 − 50R250Negative weight: distance pulls the price down (e.g. a far-away discount).
[200, 5]600 + 50R650Bigger weight: products matter twice as much.

In real ML we don't pick the weights by hand. The model learns them from data. That's what Topics 4–6 are about. First, play with them yourself below.

🐍 Python practical: one customer, then many customers 
import numpy as np

X = np.array([3, 10])     # customer features
W = np.array([100, 5])    # model weights
b = 50                    # model bias

prediction = np.dot(X, W) + b
print("Predicted spending: R", prediction)

# Many customers at once: matrix @ vector
X_all = np.array([[3, 10],
                  [1, 2],
                  [5, 18]])
print(X_all @ W)        # one dot product per row
print(X_all @ W + b)    # add the bias to every prediction
Predicted spending: R 400 [350 110 590] [400 160 640]
RememberPrediction = (each feature × its weight), added up, plus the bias. For many customers: X · w + b, one dot product per row. Bigger weight = that feature matters more. Negative weight = that feature lowers the prediction.

Topic 4

Loss

❓How wrong is the model, as one number?
Big ideaLoss is a score for how wrong the model is. Lower is better; zero means perfect. Training is all about making this number smaller.

Step 1: errors

Suppose our model guesses R80 per product, but customers really spend R100 per product. The error is the actual value minus the prediction:

Error = y − ŷ(y = actual, ŷ "y-hat" = predicted)
CustomerActual yPredicted ŷErrorError²
A1008020400
B200160401,600
C300240603,600
D400320806,400
Total20012,000

Step 2: squash the errors into one number

Mean Squared Error (MSE)
MSE = 1n Σ (y − ŷ)²

Square each error, then average: 12,000 ÷ 4 = 3,000. Squaring makes big mistakes count a lot more. Units are squared (rand²).

Mean Absolute Error (MAE)
MAE = 1n Σ |y − ŷ|

Ignore the sign, then average: 200 ÷ 4 = R50. Easy to explain: "on average we're R50 off."

For classification (yes/no answers) there's also binary cross-entropy. You'll meet it in logistic regression.

🐍 Python practical: MSE and MAE 
import numpy as np

actual    = np.array([100, 200, 300, 400])
predicted = np.array([80, 160, 240, 320])

errors = actual - predicted
mse = np.mean(errors ** 2)
mae = np.mean(np.abs(errors))

print("Errors:", errors)
print("MSE:", mse)
print("MAE:", mae)
Errors: [20 40 60 80] MSE: 3000.0 MAE: 50.0
RememberLoss tells the model how wrong it is. MSE punishes big mistakes heavily; MAE treats all mistakes equally. Training tries to reduce the loss.

Topic 5

Slope & gradient

❓Which way should a weight move?
Big ideaSlope tells you how steep a line is and whether it goes up or down. A gradient is the slope of the loss: it tells the model whether to make a weight bigger or smaller.

Slope: rise over run

Think of driving over a hill. Going up = positive slope. Going down = negative. Flat = zero.

m = y₂ − y₁x₂ − x₁ = riserun→(2, 4) and (4, 8): m = 8 − 44 − 2 = 2

A slope of 2 means: each time x goes up by 1, y goes up by 2.

Gradient: the slope of the loss

Back to the store. The model is ŷ = w · x. If we plot loss (up) against weight (across), we get a valley. The bottom of the valley is the best weight.

The gradient is the slope of that valley where you're standing right now:

  • Negative gradient (downhill to the right) → increase the weight.
  • Positive gradient (uphill to the right) → decrease the weight.
  • Zero gradient → flat ground. Possibly the bottom (but it could also be a peak or a flat spot).

For our data, at w = 80 the gradient is −300: negative, so we should increase the weight towards 100.

Topic 6

Gradient descent

❓How big a step should the model take, and what can go wrong?
Big ideaGradient descent = walk downhill on the loss valley in small steps. Each step: check the slope, then move the weight the opposite way.

The formula sheet: everything in one place

Gradient descent uses every idea from the previous topics. Here are all the formulas, in the order the model uses them, with the numbers from our store example (w = 80, data x = [1, 2, 3, 4], y = [100, 200, 300, 400]).

1Model (prediction)Topic 3
ŷ = w · x  (+ b)

Turns features into a guess. Many customers: ŷ = X · w + b.

Store example: w = 80 → ŷ = [80, 160, 240, 320]
2Error (residual)Topic 4
e = y − ŷ

How far off one prediction is. Positive means the guess was too low.

Store example: e = [20, 40, 60, 80]
3Loss function L(w)Topic 4
L(w) = 1n Σ (yi − w xi)²

The MSE written as a function of the weight. Plotting it gives the loss valley, and training searches for its bottom.

Store example: L(80) = 3,000 · L(100) = 0
4MSE (Mean Squared Error)Topic 4
MSE = 1n Σ (y − ŷ)²

Square, then average. Big mistakes count much more. Units are squared (R²).

Store example: (400+1600+3600+6400) ÷ 4 = 3,000
5RMSE (Root MSE)new
RMSE = √MSE

Undo the squaring, so the result is back in rand. Read it as a "typical" error size.

Store example: √3,000 ≈ R54.77
6MAE (Mean Absolute Error)Topic 4
MAE = 1n Σ |y − ŷ|

Average size of the miss, ignoring the sign. Less sensitive to outliers.

Store example: (20+40+60+80) ÷ 4 = R50
7GradientTopic 5
dLdw = 2n Σ xi(w xi − yi)

The slope of the loss valley at the current weight. Its sign gives the direction and its size the steepness.

Store example: −300 → increase w
8Update rule (gradient descent)Topic 6
wnew = wold − α · dLdw

Step against the slope. α (the learning rate) sets the step size.

Store example: 80 − 0.1 × (−300) = 110

The gradient descent equation

This is one of the most important equations in machine learning:

wnew = wold − α · dLdw
A · Current weight
w = 80

The weight the model is using right now. It's our starting guess: R80 per product.

B · Learning rate
α = 0.1

Controls how big a step the model takes. Small α = small, careful steps. Large α = big, risky steps.

C · Gradient
dL/dw = −300

The direction and rate of change of the loss. The minus sign in the equation makes us step downhill.

What can go wrong? Picking the learning rate

Imagine walking down a hill in the fog. You can only feel the slope under your feet (the gradient) and choose how big a step to take (the learning rate).

🐢 Too small (α = 0.01)

Tiny steps. It gets there eventually, but training takes far too long.

✓ Just right (α = 0.05)

Sensible steps that shrink as the slope flattens. Reaches the bottom quickly and safely.

💥 Too large (α = 0.16)

Giant steps jump over the bottom, each time further away. The model fails to converge.

🐍 One gradient-descent step in Python (all the formulas) 
import numpy as np

X = np.array([1, 2, 3, 4])            # feature vector (products)
y = np.array([100, 200, 300, 400])    # target (actual spend)
w, lr = 80.0, 0.1                     # current weight, learning rate

y_hat = w * X                                   # 1. predict
mse = np.mean((y - y_hat) ** 2)                 # 2. loss (MSE)
rmse = np.sqrt(mse)                             #    RMSE
mae = np.mean(np.abs(y - y_hat))                #    MAE
gradient = np.mean(2 * X * (y_hat - y))         # 3. gradient dL/dw
w_new = w - lr * gradient                       # 4. update

print("MSE:", mse, "RMSE:", round(rmse, 2), "MAE:", mae)
print("Gradient:", gradient, "New weight:", w_new)

new_mse = np.mean((y - w_new * X) ** 2)
print("New MSE:", new_mse, "New RMSE:", round(np.sqrt(new_mse), 2))
MSE: 3000.0 RMSE: 54.77 MAE: 50.0 Gradient: -300.0 New weight: 110.0 New MSE: 750.0 New RMSE: 27.39
RememberGradient descent improves a model by adjusting its weights to reduce the loss: predict → measure loss → find the gradient → step against it → repeat. The learning rate sets the size of each step, and picking it well matters.

Notebook practical: the full loop

❓Can I run the whole loop myself and explain it?
Big ideaTraining a model is a loop: predict → measure loss → find gradient → update weight, repeated. Each pass is one iteration.

What we're building

A model that predicts customer spend from products ordered: ŷ = w · x.

Data: X = [1, 2, 3, 4], y = [100, 200, 300, 400]. We start with a poor guess, w = 80, and let the loop fix it.

🐍 The complete notebook code 
import numpy as np

# Training data
X = np.array([1, 2, 3, 4])
y = np.array([100, 200, 300, 400])

# Initialise weight and learning rate
w = 80.0
learning_rate = 0.1

for i in range(20):
    predictions = w * X                                # 1. predict
    loss = np.mean((predictions - y) ** 2)             # 2. loss (MSE)
    gradient = np.mean(2 * X * (predictions - y))      # 3. gradient
    w = w - learning_rate * gradient                   # 4. update

    if i % 5 == 0:
        print(f"Iteration: {i}, Loss: {loss:.4f}, Weight: {w:.4f}")

print("\nFinal weight:", w)

# Use the trained model
new_customer = np.array([6])
print("Predicted spending: R", (w * new_customer)[0])
